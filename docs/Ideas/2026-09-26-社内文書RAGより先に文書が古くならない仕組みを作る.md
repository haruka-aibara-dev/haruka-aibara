# 社内文書 RAG より先に、文書が古くならない仕組みを作る

社内文書の多くは古い。古い文書を RAG で引いても意味がない。先に要るのは、古い文書が自動で見つかり更新される仕組み。

古くなる原因は、実態（システム・設定・組織）が変わるときに文書が一緒に変わらないこと。定期レビューでは、間隔の分だけ必ず古くなる。

## 仕組み

- **書かずに生成する**：構成・一覧・パラメータは IaC・設定・API から生成する。手書きは「なぜそうしたか」だけ
- **変更と同じ PR で直す**：文書を実態と同じリポジトリに置き、PR で AI に古くなる文書と修正案を出させる
- **変更イベントで探す**：ツール廃止・異動などをきっかけに、その名前が出る文書を探す
- **AI が実態と突き合わせる**：ずれがあれば更新案まで作らせ、承認は人
- **手順書は実行して確かめる**：自動化すれば、壊れたときに古いと分かる

人の頭にしかない情報は自動で最新にできない。確認日を出して古さを見えるようにし、確認できないものは消す。
