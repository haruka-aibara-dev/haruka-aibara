# 人間向けの社内文書は「なぜ」と「あるべき」だけ残す

「社内文書を AI に読ませれば、聞けば答えが返ってくる」という話はよく出る。ただ、社内文書の多くは古い。古い文書を RAG で引いても、古い答えが返ってくるだけで意味がない。

では文書が古くならない仕組みを作ろう、と考えていくと、その前の問いに行き着く。**そもそも、今の時代に人間向けの文書は要るのか。**

## RAG は古さを隠す

RAG がやっているのは「質問に近い文書を探して、それを材料に答えさせる」ことだけで、文書が正しいかは見ていない。人が検索していた頃は、更新日や書きぶりで「古そうだ」と疑えた。RAG を通すと、古い手順が出典付きのきれいな文章で返ってくる。**古い文書は、検索よりも RAG のほうが害が大きい。**

## なぜ古くなるか

文書が古くなるのは、**実態が変わるときに、文書が一緒に変わらない**から。

- システムの構成を変えた PR に、手順書の修正は入っていない
- ツールを乗り換えたが、旧ツール前提のページはそのまま
- 担当が異動したが、「問い合わせは○○さんへ」は残る

定期レビューは、この原因に手を付けていない。見直しの間隔の分だけ必ず古くなる。

## 実態を書き写した文書は要らない

古くなる文書の多くは、**実態を人間向けに書き写したもの**だ。

- 構成図・リソース一覧・パラメータ表
- 手順書
- 「このシステムはこう動く」という説明

書き写しは、実態と二重管理になるので必ずずれる。そして今は、AI に実態（コード・IaC・設定・ログ・チケット）を直接読ませて、**聞かれたときに、聞いた人向けに説明させる**ことができる。書き写さなければ古くならない。

RAG で読ませる相手も、文書ではなく実態のほうになる。「文書を RAG で読ませる」より「実態を AI に読ませる」ほうが、最新で、しかも質問に合わせた答えになる。

## 残るのは実態から読めないこと

実態から読めないものは、書かないと残らない。

| 残すもの | 例 | 古くなるか |
|---|---|---|
| なぜそうしたか | 設計判断・経緯（ADR） | 日付付きの記録なので、その時点の判断として正しいまま残る |
| どうあるべきか | ポリシー・ルール・制約 | 実態とずれたら、文書ではなく実態の違反。検知する対象になる |
| 約束・証跡 | 規程・契約・監査の証跡 | 文書化そのものが求められる。改訂の手続きが決まっている |
| 人の頭にしかないこと | 暗黙の判断基準・勘所 | 古くなる。下で扱う |

「あるべき」の文書は、AWS Config のルールと同じ構図になる。ルール（あるべき）と設定（実態）がずれたら、ルールを直すのではなく非準拠として検知する。文書も同じで、**ずれは文書の古さではなく、実態側の問題として扱える**。

### 人の頭にしかないこと

突き合わせる実態がないので、自動では最新にできない。「常に最新」を目指すのをやめ、**古いかもしれないことが見える**状態にする。

- オーナーと最終確認日を文書に出す
- 確認日が一定期間より古いものは、表示や検索結果で注意を付ける
- オーナーが名乗り出ないものは、[いらないページを消せる状態を作る](いらないページを消せる状態を作る.md) の「消してよいか」の定例に流す

## 残した文書は AI も読む

残った文書の読み手は、もう人だけではない。AI が実態と一緒に読んで、「なぜ」「あるべき」を踏まえて答えるための材料になる。

- リポジトリにプレーンテキスト（Markdown）で置く。Wiki に出したいなら、リポジトリから同期する
- 実態を変える PR で、AI に「この変更はあるべきに反していないか」「なぜの記録を足すべきか」を見させる（[ADRの要否をAIに判断させるリポジトリ設計](../ADR/ADRの要否をAIに判断させるリポジトリ設計.md)）

このリポジトリの `AGENTS.md` も、AI が読む前提で書いた「あるべき」の文書にあたる。

## 気をつけること

- **AI に実態を読ませるのは、権限を渡すこと。** 本番の設定やログを読める AI は、それ自体が守る対象になる。読み取り専用に絞る、読める範囲を分ける、呼び出しを記録する、といった設計が要る
- **監査で文書を求められるものは、形式として残る。** ISMS のように文書化そのものが要求されるものは、「AI に聞けば分かる」では通らない
- **実態が読めない相手には書く。** 社外・契約先・AI の権限を持たない人に渡すものは、書いて渡すしかない

## まとめ

- 古い文書を RAG で引いても意味がない。そして古くなる文書の多くは、実態の書き写し
- 書き写しはやめて、AI に実態を読ませて答えさせる
- 書くのは「なぜ」「あるべき」「証跡」だけ。これらは古くなりにくく、ずれは実態の違反として検知できる
- 人の頭にしかないことは、古さを見えるようにして、確認できないものは消す
